# Order Management Service — Project Notes

## What the service does

A Spring Boot REST API for creating and managing customer orders. It stores each order and its line items in PostgreSQL.

## Main parts

- `Order` maps to the `orders` table. It has a database ID, generated UUID business `orderNumber`, customer email, status, calculated total amount, creation time, and a list of items.
- `OrderItem` maps to `order_items`. Each line stores a product code, unit price, quantity, and an `order_id` foreign key.
- The relationship is one-to-many: an order can have multiple items. `CascadeType.ALL` saves and deletes items with their parent order, and `orphanRemoval = true` removes an item when it is removed from an order.
- `CreateOrderRequest` and `OrderItemRequest` define and validate incoming JSON. Controllers accept these DTOs rather than JPA entities.
- `OrderResponse` and `OrderItemResponse` define the outgoing JSON. Controllers return DTOs rather than exposing JPA entities.
- `OrderRepository` extends `JpaRepository` and has derived queries for business order number, customer email, and status.
- `OrderService` maps requests into entities, calculates `totalAmount` as the sum of `unitPrice × quantity`, creates the UUID order number, persists the order, and maps results to responses. Transaction handling is applied at the service layer.
- `ApiExceptionHandler` turns request validation errors into HTTP 400 field-to-message JSON and missing resources into HTTP 404 responses.

## Order rules

- Valid statuses: `PENDING`, `CONFIRMED`, and `CANCELLED`.
- If status is omitted, the request defaults to `PENDING`.
- Customer email is required and must have a valid email format.
- An order must contain at least one item.
- Every item needs a product code, positive unit price, and quantity of at least one.
- `orderNumber` and `createdAt` are generated by the service/entity lifecycle.
- `totalAmount` is calculated by the service; clients should not send it in the create/update request.

## HTTP endpoints

Base URL: `http://localhost:8080/api/v1/orders`

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/api/v1/orders` | Create an order; returns 201 Created |
| `GET` | `/api/v1/orders` | List all orders |
| `GET` | `/api/v1/orders?customerEmail=john.doe@example.com` | Filter by customer email |
| `GET` | `/api/v1/orders/{orderNumber}` | Fetch one order by its UUID business number |
| `PUT` | `/api/v1/orders/{orderNumber}` | Replace the editable order details and items |
| `DELETE` | `/api/v1/orders/{orderNumber}` | Delete an order and its items; returns 204 No Content |

Example create request:

```json
{
  "customerEmail": "john.doe@example.com",
  "items": [
    { "productCode": "PROD-101", "unitPrice": 49.99, "quantity": 2 },
    { "productCode": "PROD-202", "unitPrice": 15.00, "quantity": 1 }
  ]
}
```

Expected total: `114.98`. The response includes the generated `orderNumber`, `createdAt`, status, total, and line items.

## Database and local run

The application connects to PostgreSQL at `localhost:5433`, database `order_db`, using the `postgres` username. The configured local password is `password`.

The Docker container listens on port `5432` inside Docker and publishes it as host port `5433`. This avoids the Mac's own PostgreSQL process, which already uses host port `5432`.

Start the application from this directory:

```sh
mvn spring-boot:run
```

The application uses `spring.jpa.hibernate.ddl-auto=update` to update the local development schema from the JPA entities at startup. SQL is printed and formatted in the application logs.

## Inspect records in PostgreSQL

From a terminal:

```sh
docker exec -it order-postgres psql -h 127.0.0.1 -p 5432 -U postgres -d order_db
```

At the `order_db` prompt:

```sql
\dt
SELECT * FROM orders;
SELECT * FROM order_items;
```

Join line items to their order:

```sql
SELECT o.order_number, o.customer_email,
       oi.product_code, oi.unit_price, oi.quantity
FROM orders o
JOIN order_items oi ON oi.order_id = o.id;
```

The Docker Desktop **Exec** terminal runs inside the container, so PostgreSQL's internal TCP port is `5432`. From a database client on the Mac, connect to host `localhost`, port `5433`, database `order_db`, user `postgres`, password `password`.

## Unix socket vs TCP

Without `-h`, `psql` tries a Unix socket, a local socket file. With `-h 127.0.0.1 -p 5432`, it uses TCP, a network connection to an address and port. The TCP form above works in the Docker Desktop Exec terminal.
